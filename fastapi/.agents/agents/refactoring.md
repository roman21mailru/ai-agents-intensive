# Refactoring rules

## Когда рефакторинг уместен

- Переименование доменных концепций, когда старое имя вводит в заблуждение.
- Извлечение дублирующейся логики в сервис или helper.
- Разбиение разросшегося модуля на несколько с чёткими ответственностями.
- Изменение слоевой принадлежности — например, перенос валидации из API в сервис.

## Когда рефакторинг запрещён

- Без явной задачи — не переименовывай «заодно».
- В hotfix-ветке — только минимальный фикс.
- Если нет тестов покрывающих изменяемый код — сначала тесты, потом рефакторинг.

## Обязательные шаги перед началом

1. Убедись, что все тесты проходят до рефакторинга: `uv run pytest -q`.
2. Зафиксируй текущее состояние: `git status` — должен быть чистый рабочий каталог.
3. Создай ветку по правилу `refactor/<JIRA-KEY>-<short-description>`.
4. Найди все точки использования до начала правок: `grep -r "OldName" app/ tests/`.

## Порядок изменений

Рефакторинг должен идти по слоям — сверху вниз по зависимостям:

```
domain/       ← начинать здесь (нет зависимостей от других слоёв)
db/models     ← SQLAlchemy модель
repositories/link_repository ← методы репозитория (маппинг ORM ↔ домен)
services/     ← сервисный слой
api/          ← HTTP-слой
tests/        ← в последнюю очередь (и unit, и integration)
alembic/      ← только если меняется схема БД
```

Изменения в тестах — только после того, как основной код собран и линтеры проходят.

## Обязательные проверки после каждого файла

```bash
uv run ruff check .
uv run basedpyright
```

Не переходи к следующему файлу пока текущий не проходит статический анализ.

## Обязательные проверки в конце

```bash
uv run ruff check .
uv run basedpyright
uv run pytest -q
```

Все три должны быть зелёными до создания коммита.

## Что проверить в diff

- Все вхождения старого имени заменены — проверяй через `grep -r "OldName" app/ tests/`.
- Публичный API эндпоинтов не изменился (пути `/links` остаются `/links` если не оговорено).
- Alembic migration создана если изменилась схема БД (имя таблицы, колонки).
- Нет закомментированного кода или временных `# TODO` от рефакторинга.
- Импорты в каждом изменённом файле актуальны.

## Коммит

Один коммит на рефакторинг (если нет весомой причины дробить):

```
[agent] refactor: переименовать ShortLink → Link по всем слоям
```

Если рефакторинг большой — допустимо разбить по слоям:
```
[agent] refactor: переименовать ShortLink → Link в слоях domain и db
[agent] refactor: переименовать ShortLink → Link в слоях services и api
[agent] refactor: обновить тесты после переименования ShortLink → Link
```
