# Skill: Refactoring

## Алгоритм выполнения задачи на рефакторинг

> Рефакторинг — самый «дорогой по охвату» тип задачи: одно переименование
> может затронуть десятки файлов. Перед кодом **обязательно** собери
> полный список мест через `grep -r "OldName" app/ tests/` и пробеги его
> глазами. Если хотя бы один файл выглядит неожиданно — разберись с ним
> до того как править. Для разведки удобно использовать **Plan mode**
> AI-IDE. Артефакт «список файлов + список замен по слоям» при желании
> можно положить в `Tasks/<JIRA-KEY>/` — это полезно при рестарте сессии.

### 1. Подготовка

- Прочитать `.agents/agents/refactoring.md`.
- Прочитать `.agents/agents/architecture.md` — убедиться в понимании слоёв.
- Проверить что тесты зелёные: `uv run pytest -q`.
- Создать ветку: `git checkout -b refactor/<JIRA-KEY>-<short-description>`.

### 2. Изучение кодбазы перед правками

Перед тем как менять хоть одну строку — найти все точки использования:

```bash
grep -r "OldName" app/ tests/ --include="*.py" -l
```

Составить список всех файлов к изменению. Если хотя бы один файл
неожиданный — разобраться почему он там, прежде чем продолжать.

### 3. Изменения по слоям (строго в этом порядке)

**3.1 — domain/**
- Переименовать dataclass / TypeAlias / константу.
- Обновить аннотации типов внутри модуля.
- Проверить: `uv run ruff check . && uv run basedpyright`.

**3.2 — db/models.py**
- Обновить SQLAlchemy-модель (класс, `__tablename__` только если меняется имя таблицы).
- Если меняется имя таблицы — создать Alembic migration:
  ```bash
  uv run alembic revision --autogenerate -m "rename short_link to link"
  uv run alembic upgrade head
  ```
- Проверить: `uv run ruff check . && uv run basedpyright`.

**3.3 — db/repository.py**
- Обновить импорты, аннотации типов, имена методов если они включали старое имя.
- Проверить: `uv run ruff check . && uv run basedpyright`.

**3.4 — services/**
- Обновить импорты и аннотации типов.
- Имена методов сервиса — только если они включали старое имя (`create_short_link` → `create_link`).
- Проверить: `uv run ruff check . && uv run basedpyright`.

**3.5 — api/**
- Обновить импорты, DTO-классы, аннотации типов.
- URL-пути эндпоинтов не менять если в задаче не указано явно.
- Проверить: `uv run ruff check . && uv run basedpyright`.

**3.6 — tests/**
- Unit тесты: обновить импорты, имена Fake-классов, аннотации типов.
- Integration тесты: обновить импорты, аннотации.
- Запустить все тесты: `uv run pytest -q`.

### 4. Финальная проверка

```bash
grep -r "OldName" app/ tests/ --include="*.py"
```

Вывод должен быть пустым.

```bash
uv run ruff check .
uv run basedpyright
uv run pytest -q
uv run pre-commit run --all-files
```

Все четыре — зелёные. Если `pre-commit` поймал что-то, чего не увидели предыдущие шаги (например, `bandit` или `pip-audit`) — исправить и перезапустить.

### 5. Коммит

```bash
git add -p
git commit -m "[agent] refactor(<scope>): переименовать OldName → NewName по всем слоям"
```

Тэг и scope английские, описание — русское (см. таблицу «Язык общения» в
`.agents/AGENTS.md`).

### 6. В конце задачи

«Рефакторинг готов, все слои обновлены, тесты зелёные, `grep OldName`
пустой, коммит сделан. Идём дальше — MR, или есть правки?». Дальше — по
ответу оператора.

## Что делать если тест упал

1. Читать ошибку — скорее всего `ImportError` или `AttributeError` из-за пропущенного переименования.
2. `grep -r "OldName" app/ tests/` — найти что пропустил.
3. Исправить только это место, снова запустить тесты.

Если 3 попытки подряд тест падает на одном и том же — стоп, действуй по
`.agents/agents/error-handling.md` (это уже High severity — workaround не
лепи, разбирайся в корневой причине).

## Что делать если basedpyright ругается

Типичная ошибка — импорт старого имени в другом файле:

```
error: "OldName" is not exported from "app.domain.task"
```

Найти файл, обновить импорт. Не добавлять `# type: ignore` — это скрывает проблему.
