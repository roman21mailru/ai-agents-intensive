# Skill: Hotfix

## Алгоритм срочного исправления

> Hotfix идёт в прод срочно — **scope-дисциплина обязательна**. Перед
> кодом коротко зафиксируй для себя и оператора (одним сообщением в
> чате, не отдельным файлом): что упало в проде, какой минимальный
> фикс (≤ 20 строк), что НЕ трогаем «заодно», как откатить если станет
> хуже. Это не approval gate — это страховка от scope creep, которая
> в hotfix обходится дороже всего. Если хочется обдумать перед кодом —
> используй Plan mode AI-IDE.

### 1. Подготовка
- Прочитать `.agents/agents/hotfix.md` — там жёсткие правила hotfix.
- Создать ветку от `main`: `git checkout main && git checkout -b hotfix/<JIRA-KEY>-<short-description>`.

### 2. Минимальный фикс
- Только одно изменение — то, которое устраняет проблему.
- Никакого рефакторинга, никаких «заодно».
- Если фикс требует больше 20 строк — это не hotfix, а обычный bugfix. Остановись и согласуй смену типа задачи с оператором, не размазывай hotfix.

### 3. Regression test
- Написать тест, воспроизводящий проблему.
- Убедиться что тест зелёный после фикса.

### 4. Проверка
- `uv run ruff format .` — автоформатирование.
- `uv run ruff check --fix .` — автофикс автофиксимых правил.
- `uv run ruff check .` — должно быть зелёно.
- `uv run basedpyright`
- `uv run pytest -q`
- `uv run pre-commit run --all-files` — прогнать все хуки перед коммитом. В hotfix особенно важно: красный pre-commit = уезжающая в прод проблема.

Если что-то упало — `.agents/agents/error-handling.md`, severity для hotfix
по умолчанию High (а если падает то, что было зелёным до твоих правок —
Critical, останавливайся и зови оператора).

### 5. Коммит
- `[agent] hotfix(<scope>): <описание на русском>` — строго один коммит.
  Тэг и scope английские, описание — русское (см. таблицу «Язык общения»
  в `.agents/AGENTS.md`).

### 6. В конце задачи
«Hotfix `PROJ-XXX` готов, regression test добавлен, всё зелёное, коммит
сделан. Делаю MR на `main`?». Дальше — по ответу оператора.
